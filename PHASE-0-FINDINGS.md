## 1. What was built

- **Five frozen deterministic engines** (Workbench), composed with zero
  adapter code by the Alpha Workbench orchestrator:
  `observation-engine → opportunity-engine → decision-engine →
  conversation-engine → comparison-engine`. Each is deterministic
  (same input → deep-equal output). Declared FROZEN in
  `alpha-workbench/{orchestrator.ts, server.ts, ARCHITECTURE.md}`.
- **The Evidence Architecture** — a separate line from the five engines:
  `evidence-validator` (deterministic implementation of Evidence
  Specification v1.x, class A/B/C claim validation with reason-coded
  rejections) + `evidence-runtime` (propose → validate → graph prototype,
  one live Listen Engine LLM call) + `evidence-benchmark` +
  `evidence-shadow-compare` (two-branch LEFT-regex / RIGHT-evidence
  comparison pipeline and its two-column debug UI).
- **`coaching-runtime`** — the first prototype of the gray-band coaching
  architecture: **deterministic Teaching Move (policy) → Coaching Act →
  Narrator (the ONE LLM call) → deterministic Guardrail + Grounding →
  final text.** This is the proto-coach the pivot builds on.
- **Test Build v1** (`test-build-v1`) — a thin, stateless turn-runner over
  the `evidence-shadow-compare` pipeline with a 45s live-call timeout and a
  regex-only degradation fallback, plus a local suppression diagnostic log.

## 2. What was proven

- **The O3/O5 opportunity-ladder behavior and its "flagship fix."** O3 is
  the unquantified-result ladder; O5 is vagueness/specificity. The Milestone
  3 flagship fix suppresses `O5_vagueness` *before* `decide()` so its
  root-cause priority can no longer override a merely-added competing
  `O3_unquantified_result` candidate (`evidence-shadow-compare/test/
  pipeline.test.ts`, `opportunitySuppression.test.ts`, `ladderExclusivity.test.ts`).
- **Dimensional-unit vocabulary fixes** (`observation-engine` +
  `evidence-validator`), from the "Close Remaining Dimensional-Language Gaps"
  work order: e.g. recognizing `thou`/`thousandths` (thousandth-of-an-inch)
  as units and `dropped` as a result marker (`observation-engine/src/
  lexicons.ts`, `test/observers.test.ts`).
- **A real factual-fabrication incident, root-caused and fixed.** The Case
  001 "indicator" fabrication (a word belonging to a different case reached
  the learner). Root cause was a fixture copy error, ruled in by reading the
  routing directly rather than assuming. The fix added the **8th check,
  grounding** (`coaching-runtime/src/grounding.ts`) alongside the 7-category
  guardrail — because none of the 7 categories check factual accuracy.
- **The full regression is green:** **451 passing tests across 46 test files
  in all 14 packages, 0 failures** (re-run 2026-08-05; see Phase 0.5). This
  is the canonical baseline going forward and supersedes any earlier tally.

## 3. What Phase 0 disproved

- **"Reasoning-engine reuse" is blocked by an input-shape mismatch that was
  already hit.** `coaching-runtime`'s Teaching Move selector is deliberately
  **not** the frozen `decision-engine`: the engine consumes
  `CandidateOpportunity` (Observation-derived), a different input shape from
  Evidence Graph nodes/edges — "no code sharing was possible at this
  boundary" (`coaching-runtime/README.md` §1). A new reasoning engine cannot
  simply plug into the frozen `decision-engine`.
- **"Grounding is solved" is false.** The grounding check is an explicitly
  coarse lexical stopword-diff that its own authors report needs *ongoing*
  tuning and emits false positives on legitimate paraphrase/connector words
  (`coaching-runtime/README.md` §9). Separately, the Class B research shows
  **presence-grounding ≠ relationship/provenance-grounding**: a marker word
  can be present and admissible while the *relationship* it asserts between
  two quoted spans is fabricated (`evidence-validator/
  RESEARCH-claim-segmentation.md`).
- **A raw "personality layer" runs against a shipped, tested guardrail.**
  Guardrail category 3 forbids inferring the *learner's* personality/
  character, and the Narrator prompt forbids identity language ("never
  describe who the person IS"). A personality/persona feature must be scoped
  as the *coach's* voice, never as attribution of character to the learner.
  (See Phase 0.5 guardrail trace and the Voice/Method/Reasoning-Engine split.)

## 4. What is being preserved

- **`coaching-runtime` as the coach harness** — the pivot's structured coach
  extends this pipeline rather than starting a new harness.
- **`evidence-shadow-compare`'s `debugUI.js` / `debugUI.css`** — the
  ready-made two-column LEFT-vs-RIGHT comparison view, reused as-is for the
  planned LLM Coach Workbench by swapping the two column data sources.
- **The five frozen engines** — retained as the deterministic
  fallback/degradation path and as a benchmark baseline to measure the new
  coach against. Not modified.
- **The Evidence Validator's discriminated-union validation pattern**
  (`{ outcome, reason_code, explanation }`) — the template for any future
  `CoachingPlan` contract validator.

## 5. What is being retired or demoted

- **Lexicon-based detection as the primary "brain."** Regex/keyword lexicons
  remain valuable as a deterministic fallback and as cheap structural
  signals (hard-capped at 0.5 confidence — structural presence never proves
  substantive content). They are **demoted from primary** because they do
  not generalize; see the pivot rationale below.

## 6. Why the pivot is happening

Three separate work orders on the same night each ended the same way — by
**adding one more entry to a closed list** because a deterministic lexicon
could not generalize:

1. **"Close Remaining Dimensional-Language Gaps"** — add `thou`/
   `thousandths`/`dropped` to the observation lexicons.
2. **The O5 vagueness-suppression investigation** — closed-list
   opportunity/specificity rules needing another suppression case.
3. **The relationship-marker / claim-segmentation research** — a
   `MARKER_NOT_FOUND` failure on the closed `EXPLICIT_CONNECTIVES` list,
   where the real gap was semantic (relationship provenance), not a missing
   word.

Same shape every time: a closed list that keeps needing a manual entry, and
never covers the next unseen case. The pivot moves the primary judgment to an
LLM-centered coach (with deterministic policy, guardrail, and grounding still
wrapping it), and demotes the closed lists to fallback and structural-signal
roles where their limits are acceptable.
